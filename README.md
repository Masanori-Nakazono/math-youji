# かずのぼうけん

小学校入学までの半年で、年長児が身につけておきたい算数の土台を、
iPad をタップしながら遊んで獲得するためのアプリ。

- 全 15 の遊び × 各 3 レベル（計 45 レベル）
- 4 つの世界に整理：かずの しま／くらべる うみ／けいさんの やま／かたちの もり
- 1 レベル 8 問・1 日 10 分。時間制限も減点もなく、2 回間違えると自動でヒントが出る
- **出題はその子に合わせて変わる。**「10 は 3 と いくつ」といった項目ごとに
  正誤と最終学習日を記録し、レベル内は事実を一巡するように出し、
  「きょうの れんしゅう」は弱いところ・久しく触れていないところを厚く出す
- 星・シールブック・「きょうの れんしゅう」（10 問）で毎日続く設計
- 保護者向けページ：**「今週やること」**、直近30問と通算の正答率、
  半年のロードマップ、家庭での声かけ例
- 記録は端末の localStorage のみ。通信も送信も一切なし。単一 HTML ファイルで動作

## 出題はどう決まるか

正答率を表示するだけで出題には使わない、という状態を解消してあります。

**項目ごとの記録**　各問題は「この問題は何を聞いているか」を申告します
（`ten:3` = 3と7で10、`trace:4` = 4の書き方、`sum:3+2` など）。
Store はそれぞれについて〈出題数・一発正解数・最終出題日〉を持ちます。
おはなしの 3+2 としきの 3+2 は同じ項目です。同じ事実だからです。

**レベルの中**　出題器を最大 7 回まで引き直し、その回で既に出た項目を避けます。
「10の おともだち（◯と いくつで10）」は 9 種の事実に対し 8 問なので、
以前は平均 5.7 種しか出ず 3 種に触れないまま終わっていました。いまは 8 問で約 7.9 種です。

**きょうの れんしゅう**　重み付き抽選です。重みは
〈直近の不正解率 × 最終学習からの日数 × 遊びごとの focus × 到達度〉で、
1 遊び最大 3 問・1 レベル最大 2 問の上限を付けています。

| | 従来 | いま |
|---|---|---|
| いくつと いくつ でつまずいている子 | 0.66 問/日 | 約 2.0 問/日 |
| 10の おともだち でつまずいている子 | 0.66 問/日 | 約 2.0 問/日 |
| 他の 13 遊び | 0.58〜0.76 問/日 | 0.40〜0.63 問/日（捨てない） |
| 得意な子・初日 | 均等 | 0.55〜0.98 問/日（広く出る） |

**★と解放**　★は「一発で正解した問題の割合」で付きます。全問=3、75%以上=2、
50%以上=1、それ未満=0。★0 では次のレベルは開きません。ただし
**3 回まじめに挑戦すれば開きます**。5 歳児を動かせない鍵の前で止めないためです。
シールは ★1 以上のときだけ出ます。

進め方の目安（保護者ページにも掲載）
1. **1〜2か月め** かずの しま を中心に。まず 10 までを確実に
2. **3〜4か月め** いくつと いくつ → 10の おともだち。ここが山場
3. **5〜6か月め** たしざん・ひきざん と、とけい・くらべる系で入学後の単元に先に触れる

## iPad に入れる

**方法 A：ホーム画面に追加（おすすめ）**
1. `dist/kazu-no-bouken.html` を iCloud Drive などに置くか、任意の場所に公開する
2. Safari で開く → 共有ボタン → 「ホーム画面に追加」
3. アイコンから起動するとブラウザの UI が消え、アプリのように全画面で動く

**方法 B：ファイルをそのまま開く**
`dist/kazu-no-bouken.html` を AirDrop などで iPad に送り、ファイルアプリから Safari で開く。
ただし `file://` で開くと iPadOS 側がデータ保存を許可しないことがあり、**その場合は
学習の記録が毎回消えます**（保護者ページに警告が出ます）。半年続けるなら方法 A を
使ってください。ホーム画面に追加していない Safari のタブも、7 日間使わないと
iPadOS が保存データを破棄します。

いずれも初回だけネットワークがあると Google Fonts が読まれます。オフラインでも
iPad 内蔵のヒラギノ丸ゴにフォールバックするので、見た目が少し変わるだけで全機能が動きます。

## 記録が消えないようにする

学習の記録は **localStorage** に入ります。ここには 2 つの落とし穴があります。

1. **記録は URL（オリジン）ごとに完全に別物です。** GitHub Pages の URL、Artifact の URL、
   AirDrop で渡したファイル（`file://`）は、同じアプリでも互いの記録を見られません。
   **使う入り口をひとつに決めてください。**
2. **ホーム画面に追加していない Safari のタブは、7 日使わないと iPadOS が保存データを
   破棄します。** ホーム画面のアイコンから起動していれば対象外です。

そのうえで、保護者ページに **書き出し／読み込み** を用意しています。

- **記録を書き出す（ファイル）** … `kazu-no-bouken-YYYYMMDD.json`（数 KB）を保存
- **コピー** … 同じ内容をクリップボードへ。メモアプリに貼って保管できる
- **記録を読み込む** … ファイルを選ぶか、枠に貼り付けて復元
- **読み込み方** … 「合体する」（既定）はいまの記録と読み込んだ記録の良いほうを残す。
  同じファイルを二度読み込んでも数字は増えません。「おきかえる」は丸ごと差し替え

端末を変えるとき、URL を移すとき、Safari のデータを消す前に書き出しておけば復元できます。

**動作要件**：iPadOS 16.2 以降（`color-mix()` と `:focus-visible` を使っています）。
それ以前の iPad では図形の輪郭など一部の色が出ません。

**音声について**：問題文は日本語で読み上げられます。声が出ない場合は
iPad の 設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 日本語 で
Kyoko などを追加してください。文字だけでも遊べます。

## 公開（GitHub Pages）

`main` に push すると `.github/workflows/pages.yml` が走り、`src/` からビルドし直した
`dist/kazu-no-bouken.html` を `index.html` として GitHub Pages に配置します。

ワークフローが Pages の有効化まで行うので、リポジトリ側の手動設定は不要です。

ワークフローは `./build.sh` を実行したあと `dist/` に差分が出たら失敗します。
ビルドし忘れたまま古いページが公開されるのを防ぐためです。

## テスト

```bash
python3 -m http.server 8731     # プロジェクト直下で
```
ブラウザで `http://127.0.0.1:8731/test/index.html` を開くと回帰テストが走ります。
アプリを iframe に読み込み、実際に答えをタップして「そのあと何が起きたか」を検証します。

問題を **作れる** ことだけを確認しても、対話のバグは1つも見つかりません。
実際に初版では、正解を押した後の挙動を誰も検証していなかったために、
「穴が2つある問題が1つ目で終わってしまう」「前の問題のタイマーが次の問題を
勝手に正解にする」といったバグが素通りしていました。テストはそこを狙って書いてあります。

| 検証 | 何を守っているか |
|---|---|
| no question completes while blanks remain | 複数回答の問題が途中で終わらない |
| one answer never advances more than one question | 1回の正解で1問だけ進む |
| every level is playable through to the result screen | 全45レベルが最後まで遊べる |
| leaving a question cannot advance the next level | 中断しても前の問題のタイマーが残らない |
| a story animation cannot write into the next question | アニメ中に抜けても次の画面を壊さない |
| leaves no handlers behind | 共有ノードにリスナが溜まらない |
| a hint is never stacked up | ヒントが重複しない |
| two wrong answers always change something on screen | 読み上げオフでも必ず画面が反応する |
| tracing counts misses | なぞり書きが常に★3にならない（保護者ページの数字が嘘にならない） |
| tapping the correct answer twice cannot strand the question | 二度タップで空欄を飛ばさない・例外を出さない |
| one session works through the fact set | 1回のレベルが同じ事実を出し続けない |
| a session under half right earns no star | 半分に満たない回で次が開かない |
| three honest attempts open the next level | 3回やれば必ず先へ進める |
| a clear pass opens the next level | 通れば開く |
| the daily set aims at the weak topics | 弱点を厚く出しつつ他も捨てない |
| clock hours read よじ / しちじ / くじ | 時計の読みが「よんじ」にならない |
| no role=button without keyboard support | 見た目がボタンなら必ずキーボードでも押せる |
| answer sets have no duplicate labels | 選択肢が破綻しない |
| every sticker slot has its own emoji | シールが重複しない |
| a backup restores the records exactly | 書き出した記録が完全に戻る |
| importing the same backup twice does not inflate | 二重読み込みで数字が増えない |
| merging keeps the higher star count | 合体しても良いほうが残る |
| a wrong file is rejected without destroying the records | 誤ったファイルで記録が壊れない |

## 遊びを増やす

`src/js/1x-g-*.js` に `Games.add({...})` を足すだけで、ホーム画面・レベル選択・
「きょうの れんしゅう」・保護者ページのすべてに自動で載ります。

```js
Games.add({
  id: 'myGame', name: 'あたらしい あそび', ico: '🎲',
  world: 'shima',                 // shima | umi | yama | mori
  color: 'var(--c-blue)',
  aim: '保護者ページに出る「この遊びで つく ちから」',
  levels: [
    { t: 'レベル名', d: 'ひとこと説明', n: 8, make(api){
        api.setPrompt('といかけ', '読み上げる文');
        api.field.append(/* 問題の見た目 */);
        api.item('myGame:3', '3 の れんしゅう');   // この問題が聞いていること
        api.buildChoices([1,2,3], 2);   // 正解は 2
        api.onHint(() => { /* 2回間違えたときに呼ばれる */ });
      } }
  ]
});
```

`api.correct()` を呼べば正解、`api.wrong(el)` で不正解。自作の操作で解かせる遊びは
この 2 つを自分で呼べば、進行・星・シールはエンジン側が面倒を見ます。

**`api.item(key, label)` を呼んでください。** その問題が何を聞いているかの申告です。

```js
api.item('ten:' + a, a + ' と ' + (10 - a) + ' で 10');
```

これがあると、(1) 同じ事実が 1 レベル内で繰り返されなくなり、
(2) 間違えた事実が「きょうの れんしゅう」に戻ってきて、
(3) 保護者ページの「つまずいている中身」に `label` がそのまま出ます。
申告しない遊びは従来どおり完全ランダムに出ます（壊れはしません）。

`Games.add` の `focus`（既定 1）はカリキュラム上の優先度で、
「きょうの れんしゅう」の重みに掛かります。いくつと いくつ／10の おともだちが 1.7 です。

問題の見た目は、書いたあとにエンジンが `--u` を伸縮させて playfield いっぱいに
合わせます（`UI.fitPlayfield`）。サイズは `--u` の倍数で書いてください。
`px` 直書きは拡大されません。

**遅延処理は必ず `api.later(fn, ms)` を使ってください**（`setTimeout` は使わない）。
問題を離れると自動でキャンセルされるので、アニメーションの途中で「もどる」を
押されても、前の問題が次の問題を書き換えることがありません。

複数の答えを順に聞く問題は `buildChoices` の `onPick` で `false` を返します。
`false` のあいだ問題は開いたままになり、最後の正解でだけ次へ進みます。

```js
api.buildChoices(values, answer, {
  onPick(){ /* 1つ埋める */ return more ? false : true; }
});
```
