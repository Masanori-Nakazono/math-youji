# かずのぼうけん

小学校入学までの半年で、年長児が身につけておきたい算数の土台を、
iPad をタップしながら遊んで獲得するためのアプリ。

- 全 16 の遊び × 各 3 レベル（計 48 レベル）
- 4 つの世界に整理：かずの しま／くらべる うみ／けいさんの やま／かたちの もり
- **入学前の 48 レベルを全部クリアすると、5 つめの世界「1ねんせいの きょうしつ」が開く。**
  小学1年生の1学期にあたる 4 遊び × 3 レベル。中心は *同じものの集まり* と *1対1対応*。
  **初日から鍵付きで見えていて**、ホーム・シールブック・リザルトの3か所が
  「あと ◯レベル」を数えます
- 1 レベル 8 問・1 日 10 分。時間制限も減点もなく、2 回間違えると自動でヒントが出る
- 初めて遊ぶ子は **「はじめの ぼうけん」10 問**で現在地を見つける。結果は能力ラベルや
  ロックには使わず、ホームの **「いまの おすすめ」**を決めるためだけに使う
- **出題はその子に合わせて変わる。**「10 は 3 と いくつ」といった項目ごとに
  正誤と最終学習日を記録し、レベル内は事実を一巡するように出し、
  「きょうの れんしゅう」は弱いところ・久しく触れていないところを厚く出す
- 毎日の入り口は 2 つ。**「きょうの れんしゅう」**（10 問・広く復習）と
  **「にがて あつめ」**（10 問・つまずいている 3〜4 個の事実だけを、それぞれ何度も）。
  子どもの画面と保護者ページでは **「とっくん」🎯** と表示します——「にがて」は
  5歳にとって自分への判定に聞こえるからです
- **「いまの おすすめ」はロードマップ順に 20 の遊びすべてを歩きます。**
  返すのは「まだクリアしていない最初のレベル」です。かりのシール（別の日の確かめ待ち）は
  クリア扱いで先へ進み、確かめで届かなかったときだけそのレベルに戻ります。
  3回挑戦してもクリアできないレベルは**3日休ませて先へ進み**、その後また戻ります
- **まちがえたときは、何をまちがえたかを見ています。**「10は4といくつ」に 4 と答えた
  （見えている方を言った）のか 5 と答えた（1つずれた）のかを分類して数え、
  その場のことばと保護者ページの文章を変えます。「1つ多く／少なく数えています」は
  答えが*数*の問題でだけ言います（「どっちが おおきい」で 8 のかわりに 7、は数え違いではない）
- **はじめて開くレベルは、テストから始めません。**1問目は 👆 の手がやり方を見せて答え
  （「みてて」）、2問目は道具を出したまま一緒に解きます（「いっしょに」）。この2問は
  ★にも記録にも数えず、そのあとに本番の8問が続きます。問題の横の 👀「みせて」を押すと、
  まちがえる前でも道具が出ます
- **★1〜★2 のクリアは「かりの シール」です。**別の日の確かめ（3問中2問を1回目で正解）で
  色がつきます。1ねんせいの扉は色のついたシールだけを数えます（「いまの おすすめ」は
  かりのシールで先へ進み、確かめで届かなかったレベルに戻ります）。
  ★★★（8問すべて1回目で正解）は、その場で色がつきます
- **まちがえたら、やり方に戻します。**2回目で、その遊びの「道具」が盤面に出て声で
  言います（数える・あいたマスを埋める・端をそろえる…選択肢は減らしません）。
  4回目で 👆 の手がやり方を最後まで見せ、「こたえを みる」が出ます。
  6回目でアプリが答えを見せて一緒に終わらせます
- **1日の目安（1レベル＋れんしゅう＝18問。はじめてのレベルの見本2問や、別の日の確かめ3問も数えます）に届くと、リザルトが「きょうは ここまで」と
  言い、明るいボタンがホームになります。**ロックはしません
- 星・シールブックで毎日続く設計。シールブックは**残っているレベルを名前で並べ**、
  そのままタップして始められます。ホームのシール棚が 1ねんせいの きょうしつまでの
  道のりを**ゲージ（のこり10レベル以下は数えられる●）**で常に出します
  （「あと ◯レベル」という数字は、大人向けにラベルに残っています）
- ホームに**「ほしい シールを えらぼう」**が出ます。いま遊べる未クリアのレベルから
  3枚までを絵で選び、何をすればもらえるかを先に聞いてから始められます。通常の
  クリア判定は変えず、★1〜★2のシールが別の日の確かめまで「かり」なのも同じです
- 得意を終えたあとの入り口に**「ちいさな ぼうけん」**があります。4問だけの短い
  支援つき練習で、ヒントを使っても最後まで終えると1日1枚のぼうけんシールをもらえます。
  このシールは「取り組んだ」記念であり、レベルのクリア・次の鍵・習得の記録には入りません
- 集めた通常シールはホームの 🏡 **「じぶんの しま」**で自由に置けます。背景を選び、
  シールを選んで島をタップすると配置・移動できます。配置には正解も期限もなく、記録は
  端末内とバックアップにだけ保存されます
- 画面で遊んだ後は、配膳・おやつ分け・形探しなど、写真も通信も使わない
  **「きょうの さんすう ミッション」**へ。「できた」は**おうちのひとが2秒長押し**
  （記録を消すときの大人用ゲートは使いません）。翌日に「どうやったか」を言葉で振り返る
- 保護者向けページ：**「今週やること」**、**まちがえ方の型**、**「入学まで あと◯日」と
  いまのペースでの到達見込み**、**正確さと速さの2軸**（直近30問の正答率と、答えが出るまでの時間）、
  遊びごとの「つく ちから」、半年のロードマップ、家庭での声かけ例
- 記録を1か月書き出していないと、ホームの「おうちのかたへ」に印が付きます
  （子どもの画面は何も変わりません）
- 記録は端末の localStorage のみ。記録の送信は一切なし。単一 HTML ファイルで動作
  （ネットにつながっているときだけ、表示用のフォントを Google Fonts から読み込みます）

## 数えるだけでは、思い出せるようにならない

このアプリの量の課題は、全部「1つずつタップして数える」で解けていました。
それは*数える*練習で、**かたまりを見る**練習ではありません。
「7は5と2」を思い出せる子は、その前に 7 を〈5と2〉として**見て**います。

**ぱっと みて いくつ**（新）　ドットを 0.9〜1.0 秒だけ見せて隠し、いくつだったかを
聞きます。数える時間がないので、かたまりとして見るしかありません。

1. **1〜5 ぱっと みて** … サイコロの目の配置。1〜5 をかたちで覚える
2. **5と いくつ** … 6〜10 を「上の段に5・下の段に残り」で見せる
3. **ふたつの かたまり** … 3 と 4 を一瞬見せて「ぜんぶで いくつ？」（0〜10 キーパッド）

まちがえたときのヒントは、**もう一度、今度は隠さずに見せる**ことです。
当てずっぽうの精度を上げてほしいのではなく、見えてほしいので。**この遊びだけ、
ヒントは1回目のまちがいで出ます。**盤が伏せられたまま「もういちど やってみよう」と
言われても、子どもにできるのは当てずっぽうだけだからです（`api.coach({ after: 1 })`）。

**正解したときも、もう一度見せます。**　以前は正解すると ◯ が出て次の問題へ進み、
子どもは自分が言った数がどんな並びだったのかを**一度も見ないまま**でした。
7 を〈5と2〉として*見えるように*するための遊びなのに、その並びと数がつながる瞬間が
なかったということです。いまは正解の直後に盤を開き、「5と1で、6」と読み上げます。

## 当てるだけではなく、作って確かめる

選択肢から正解を探すだけでなく、既存の世界の中に次の生成課題が混ざります。

- 同じ数を広げて並べても数は変わらないことを確かめる（数の保存）
- 6〜9 を異なる 2 通りに分ける
- 3 つの数字を選んで 10 を作る
- 2 つの絵を自分で選び、繰り返しのきまりを作る

正解が一つに決まらない問題を入れることで、「用意された答えを当てる」だけでなく、
自分の考えを作り、別のやり方を試す経験を増やしています。

**5のまとまりに揃えました。**　`groupNode`（すうじ どれかな）だけが量を **6列**の
マス目で並べていて、9 が「6と3」、8 が「6と2」として提示されていました。
テンフレームも `partFrame` もヒントの枠も、アプリの他のすべての量表示は5列です。
**「数字の形」と「量」を結びつけることだけを仕事にしている遊びが、
アプリ全体の5構造と喧嘩していた**ので、5列に直しました。

**逆唱を足しました。**　保護者ページには最初から「10から逆に数える方が難しく、
効果があります」と書いてありましたが、それを練習するレベルがありませんでした
（`skipCount` は増える方向だけ、`nextBefore` は1歩だけ）。
かずの じゅんばん L3 に「1ずつ へって いくよ。つぎは？」が入ります。
くり下がりの素地です。

## 画面にあるものと、答えが合っていること

`.mrow`（棒グラフの1行）は、行の先頭に鉛筆アイコンを置いて棒を並べるために
作られました。あとから追加した2つの遊びが、**数える対象そのものが並ぶ行**に
この形を流用し、先頭のアイコンも一緒に引き継いでいました。アイコンは行の中身と
同じ絵文字・同じ文字サイズなので、子どもから見ればただの「もう1個」です。

- **なかまづくり L2**「🐰 どうぶつの なかまは いくつ？」の行に動物が **6匹**
  見えていて、正解は **5**。しかも選択肢は 5・2・7 で、**画面どおりに数えた 6 が
  そもそも無い**。数える対象の 45% がこの状態でした
- **ひきざん L3**「ちがいは いくつ」で、式が `10 − 8` のとき画面には風船 **11個**と
  ぶどう **9房**

正しく数えた子が「まちがい」になるのは、このアプリでいちばん起きてはいけないことです。
なかまづくりは行の見出しを**ことば**（くだもの・どうぶつ…）にし、幅を固定して
どの行も同じ位置から始まるようにしました（絵グラフの「はしをそろえる」は保ったまま）。
ひきざんは見出しそのものを外しました——行に並んでいるもの自体が、それが何かを言っています。

## 1対1が、1対1に見えること

「1たい1で くらべる」は、ペアにして**あまりを見る**遊びです。あまりが
そのまま「ちがいは いくつ」（求差）になるので、盤面が読めることがすべてです。

その盤面が読めていませんでした。行が `flex-wrap: wrap` の中央揃えだったので、
200回描画して出た**23通りの個数の組み合わせのうち、上下の行が同じ位置から始まって
1行に収まった「個数の違う」組は一つもありません**でした。魚5匹の下に星が 5＋2 で
2段に折り返し、折り返さない組は左右にずれる。どちらでも「1つ上に1つ」が成立しません。
折り返しは`はみ出し`ではないので、`UI.fitPlayfield` の自動縮小も効きませんでした。

いまは1行＝**ペアの位置ぶんの固定幅グリッド**（`--pn` 列 × `--u*6`）です。
上下の行は必ず同じ列に並び、折り返さず、**あまりは必ず右端にはみ出して残ります**。
「おなじ かずに する」で足すマスも同じ列に入るので、あまりの真下に空きマスが並びます。

## 正解を、問題の中に書き戻す

「9 ＋ 1 ＝ ?」で 10 をタップすると、◯ が出て 950ms で次の問題へ——
**式は「9 ＋ 1 ＝ ?」のまま**でした。`?` を残したまま終わる出題器が13個、
60レベル中およそ20レベルあります（たしざん・ひきざんの全6レベル、20までの かず、
しきに かこう、いくつと いくつ、10の おともだち、かずの じゅんばんの数直線）。

いくつと いくつ L3 と 10の おともだち L2 は、もともと**正解の直後にテンフレームを
埋めて見せて**いました。同じことを全体の既定にしただけです。

```js
api.buildPad(ans, revealed(() => fillBlank(box, ans)));
```

`revealed()` は `buildChoices` / `buildPad` に渡すオプションを組み立てます。
正解したときに `show` を呼び、次の問題までの間を（既定 1300ms に）伸ばします。
`fillBlank()` は式の `?` にも数直線の空きマスにも使えます。

5歳にとって、自分が選んだ数が**その文の中に入って読める**瞬間が、
その文が意味を持ち始める瞬間です。◯ をもらうことではありません。

## ぜんぶ集めたら、小学1年生へ

入学前の 48 レベルには、シールが 96 枚あります（1レベルにつき、クリアで1枚、
全問を1回目で正解するともう1枚・金色）。**鍵になるのは、そのうち「クリアのシール」
48 枚だけです。**それも**色のついた**（★★★で取ったか、別の日に確かめた）シールだけです
（下の「当てずっぽうでは、シールに色がつかない」）。48 レベルを全部クリアして色がつくと、ホームに 5つめの世界
「1ねんせいの きょうしつ」が増えます。そろった瞬間のリザルト画面が
「**しょうがっこう 1ねんせいの もんだいが できるよ！**」と読み上げます。

条件を別に用意していないのは意図的です。シールブックは子どもが最初から見ている
目標で、その目標がそのまま次の部屋の鍵になっているほうが、「ここまで来たら次」が
説明なしで伝わります。

**金のシールは鍵に入れていません。**　1枚ごとに「全問1回目正解」の回を1度出す
必要があり、それを 48 レベル分そろえるのは、このアプリ自身が薦めるペース
（1日1レベル・10分）だと半年をはるかに超えます。モンテカルロで見積もると、
「シールが足りないレベルだけを最短で回す」という現実にはあり得ない遊び方でも
中央値 174 日、子どもが好きなレベルを選ぶと 601 日でした。クリアのシール 48 枚
だけなら、同じ条件で 48 日 / 213 日です（どちらも、かりのシールと別の日の確かめを入れる前の見積もりです）。**1年生の1学期の内容が1学期に間に合わない
のでは、この世界を作った意味がありません。**金のシールはシールブックに残り、
あとから取りに戻れる目標のままです。

**鍵は最初の日から見えています。**　ホームの世界一覧に「1ねんせいの きょうしつ」が
最初から並び、4つの遊びの名前とアイコンが、鍵マーク付きの灰色のカードで見えます。
一度は「まだ遠い鍵を見せても仕方がない」と隠していましたが、それは*鍵の向こうに
何もないとき*の話です。「なかまづくり」「20までの かず」が名前で見えているからこそ、
シールを集める理由になります。カードを押すと「ぜんぶの レベルを クリアすると あそべるよ」と
言ってシールブックへ飛びます。数はそこにあるからです。

残りは2か所で言います。シールブック（96枚の下に、鍵のかかった24枚がそのまま
並んでいます）と、シールを1枚もらうたびにリザルト画面が出す
「1ねんせいの きょうしつまで **あと ◯レベル**」。残り6レベルを切ると
「もうすぐ ひらくよ！」に変わって色がつきます。この数は**色のついたシール**で動くので、
かりのシールをもらった日には動かず、確かめで色がついた日に動きます。**枚ではなくレベルで数えます。**
金のシールをもらっても鍵の数字は動かないので、「シールをもらったのに数が減らない」
という見え方をしないためです。

ホームの足元にも同じ進捗バーの帯を置いていましたが、やめました。世界一覧の
鍵付きカードが同じことをすでに言っていて、帯とシール棚で下辺が二段になると、
肝心の地図が画面のまん中の帯一本ぶんに痩せるからです。

中身は「先取りの計算」ではありません。1年生の1学期は、入学前にやったことを
**別の聞き方でたどり直します**。

- **なかまづくり**（同じものの集まり）… かぞえよう は「いくつ？」だけを聞きます。
  1年生は先に**まとまりを作らせて**から数えさせます。「6こ」は机の上の全部の数では
  なく、「くだもの」というまとまりを決めた人がいて初めて言える数だからです。
  L3 は答えが一つに決まりません（集める仲間を自分で決めます）
- **1たい1で くらべる**（一対一対応）… どっちが おおい は両方を数えて比べます。
  1年生は**ペアにして、あまりを見ます**。この「あまり」がそのまま「ちがいは いくつ」
  （求差のひきざん）になるので、指でペアを作った経験が 8−5 の意味を支えます
- **20までの かず** … 10 のわくは「10個」ではなく「1つのまとまり」。
  くり上がりの前に、ここが要ります
- **しきに かこう** … たしざん・ひきざん が「答えは？」を聞くのに対し、
  ここは「この話はどの式か」「この式はどの話か」を聞きます

**行き止まりは作りません。**　クリアは ★1つ以上（8問中4問を1回目で正解）で、
★0 でも 3 回まじめに挑戦すれば次のレベルは開きます。それでも とけい L3 や
かたちづくり で止まることはあり得るので、保護者ページから手で開けられるように
してあり、一度開けたら閉じません。

**自動で開いた扉も閉じません。**　扉はシール棚から毎回計算していたので、
のちのリリースで入学前のレベルを1つ足すと、すでに教室に入っていた子の前で
また鍵がかかる作りでした。いまは初めて開いた時点で記録に書き（`g1Reached`）、
保護者が手で開けた印（`g1Open`）とは分けて持っています。保護者ページが
「おうちの方の操作で開いています」と言うのは後者のときだけです。

## 出題はどう決まるか

正答率を表示するだけで出題には使わない、という状態を解消してあります。

**いまの おすすめ**　ホームのいちばん左にある、その子の毎日の入り口です。
以前ここが前へ進める経路は `count / flash / numeral / seq / bond` の
**5遊び・15レベルだけ**でした。残る11遊び（`ten`・`add`・`sub`・`clock` など）に
行ける道は「直近4問以上あって正答率75%未満」という*救済*の1本しかなく、
つまり**子どもが自分で見つけて、そこでつまずいた後**にしか案内されませんでした。
15レベルを終えると、関数は最後の行で `bond:0`——すでに★★★のレベル——を
返し続けます。

180日ぶんを実際の出題器で回すと（毎日「きょうの れんしゅう」10問＋「いまの
おすすめ」1レベル、5試行の中央値）、クリアできたのは
**正答率95%で48中15レベル／90%で18／85%で20／80%で31／75%で33**。
どの帯でも扉は開かず、しかも**上手な子ほど進みません**——救済しか
前進経路がないので、正確な子ほど新しい遊びを差し出されないからです。

いまは 5 点が変わっています。

1. 経路が**ロードマップ順の全遊び**になりました（`ROADMAP`。ここに名前が無い
   遊びを後から足しても、末尾に自動で入って落ちません）
2. 返すのは**「まだクリアのシールが無い、最初の開いているレベル」**。
   ★★★のレベルが返ることは構造的に無くなります。かりのシール（別の日の確かめ待ち）は
   クリア扱いにします——取った当日にまた名指しすると、クリア直後に同じレベルへ戻されるからです。
   確かめで届かなかったときは未クリアに戻り、ここに返ってきます（扉のほうは色のついたシールだけを数えます）
3. 救済のしきい値を **75% → 60%** に下げました。75%は★★が付く水準で、
   引き止める理由になっていません。救済は「詰まっているとき」のためのものです
4. 救済するのは**まだクリアしていないレベルだけ**です。クリア済みのレベルの
   正答率が落ちても、それは「きょうの れんしゅう」と「にがて あつめ」が拾います。
   以前は救済に出口が無く、クリア済みで直近 40% の子が同じレベルを毎日名指しされ、
   シミュレーションでは抜けるまで中央値 49 日かかっていました。未クリアのレベルは
   クリアすれば救済から外れるので、それ自体が出口になります
5. **3回挑戦してもクリアできないレベルは、3日休ませます。**3回挑戦すれば次のレベルは
   開くのに、おすすめは「最初の未クリア」を返し続けていたので、まだ越えられない
   レベルが1つあると毎日そこだけが名指しされ、ロードマップのその先が一度も
   出てきませんでした。休んでいる間は次の未クリアへ進み、3日たつと戻ります
   （ほかに名指しできるものが無いときは、すぐに戻ります）

同じ回し方で、扉が開くまでの日数は **48日（95%）／67日（75%）／119日（65%）**
（各3試行の中央値。65% の帯はばらつきが大きく 108〜186日）。どの帯でも
**半年のうちに 48/48 に届きます**。下の「クリアのシール48枚なら 48日／213日」
という見積もりと、ようやく噛み合いました（この日数は、かりのシールと別の日の確かめを入れる前に測ったものです）。

**項目ごとの記録**　各問題は「この問題は何を聞いているか」を申告します
（`ten:3` = 3と7で10、`trace:4` = 4の書き方、`sum:3+2` など）。
Store はそれぞれについて〈出題数・一発正解数・最終出題日〉を持ちます。
おはなしの 3+2 としきの 3+2 は同じ項目です。同じ事実だからです。

**レベルの中**　出題器を最大 7 回まで引き直し、その回で既に出た項目を避けます。
「10の おともだち（◯と いくつで10）」は 9 種の事実に対し 8 問なので、
以前は平均 5.7 種しか出ず 3 種に触れないまま終わっていました。いまは 8 問で約 7.9 種です。

**きょうの れんしゅう**　重み付き抽選です。重みは
〈直近の不正解率 × 最終学習からの日数 × 遊びごとの focus × 到達度〉で、
1 遊び最大 3 問・1 レベル最大 2 問の上限を付けています。

`focus`（カリキュラム上の優先度）は**記録がたまるにつれて効いてきます**。初日は
どのレベルも「不正解率も最終学習日も同じ」なので、以前は focus だけが差になり、
まだ 10 まで数えられない子にいちばん難しい「いくつと いくつ」が最優先で出ていました。
いまは直近 8 問ぶんの記録がたまるまで focus は 1 に近く、代わりに**まだ何も記録が
ない子には かずの しま を厚く**出します（ロードマップの 1〜2 か月めが、保護者ページの
文章ではなく出題そのものに入っている、ということです）。

**にがて あつめ**　「きょうの れんしゅう」は*復習*の器です。10 問を解放済みの全
レベルに配るので、〈4 と 6 で 10〉のような**個々の事実に届くのは 3 週間に 1 回**
程度でした（21 日 × 5 試行の実測で 1 事実あたり平均 0.9 回、9 事実のうち平均 2.8 個は
1 回も出ない）。しかもレベルを直接遊んでも同じで、1 レベル内で同じ事実を繰り返さない
ためのシャッフルバッグが、同時に「苦手を集中して練習する」ことも封じていました。

そこで器を分けました。**にがて あつめ**は、記録上いちばん苦手な 3〜4 個の事実だけを
袋に入れ、10 問を A・B・C・A・B・C… と回します（続けて同じ問題を出すと前の答えを
写すだけになるので、間を空けます）。同じ 21 日の実測で、1 事実あたり 0.9 回 → **4.2〜4.8 回**、
最多の事実は 2〜3 回 → **14 回**になります。

入り口は 2 つ：ホームの「とっくん」と、リザルト画面の「とっくん する」
（★★以上で次のレベルがあるときは「つぎの レベルへ」を主ボタンにして先頭に置き、
こちらは2番手。レベルで★0のときは、見出しも声も「もう いちど」なので
「もういちど」を主ボタンにし、こちらは2番手）。以前この画面は、苦手を
3 つ名指ししたうえで「つぎの レベルへ」だけを目立たせていました。
リザルトは苦手な事実を名前で並べますが、名前そのものはボタンにしません——
同じ練習を始める 43px の小さなボタンが 3 つ並ぶと、3 つの別の選択肢に見えたからです。
リザルトにも 🔊 があり、声は「オレンジのボタンで、次のレベルに行けるよ」のように
明るいボタンが何をするかまで言います。★0 のときは空の星3つと「8もん中 2もん」を出さず、
「さいごまで がんばったね」と出します（正解数は★★以上のときだけ）。

ホームの帯（`.dailies`）は**必ず1行**です。「いまの おすすめ」「きょうの れんしゅう」
「きのうの ミッション」「にがて あつめ」は日によって 1〜4 本立ちますが、以前は
1 本ずつが横幅いっぱいの帯だったので、4 本立つ日は地図が画面の下の帯一本ぶんに
なりました。いまは横に並べて等分し、3 本以上のときはマスコットを引っ込めて
名前に幅を譲ります（3 本以上のときは説明文を消し、名前は分かち書きの空白でだけ
2 行に折り返します——「いまの／おすすめ」であって「いまの おす／すめ」ではない）。

どのレベルでその事実を聞けるかは、記録の側が覚えています（`facts[key][4]`）。
`api.item` を申告している遊びなら、あとから追加した遊びでも自動で対象になります。

| | 従来 | いま |
|---|---|---|
| いくつと いくつ でつまずいている子 | 0.66 問/日 | 約 2.0 問/日 |
| 10の おともだち でつまずいている子 | 0.66 問/日 | 約 2.0 問/日 |
| 他の 13 遊び | 0.58〜0.76 問/日 | 0.40〜0.63 問/日（捨てない） |
| 得意な子・初日 | 均等 | 0.55〜0.98 問/日（広く出る） |

初日の世界ごとの配分（実測・記録ゼロの状態）：かずの しま が けいさんの やま の
3 倍以上出ます。やまも 0 にはしません。

**選ぶ から 思い出す へ**　けいさんの やまの上位レベル（いくつと いくつ L3 /
10の おともだち L2 / たしざん L3 / ひきざん L3）は、3択ではなく **0〜10 の
キーパッド**で答えます。3つから選ぶのは *再認* で、これらのレベルが目標に
している「考えずに言える」は *再生* です。別の能力で、くり上がりの計算で
効くのは後者だけです。当てずっぽうの正解率も 33% → 9% に下がります。
2回まちがえると、キーを減らす代わりにテンフレームが戻り、空いたマスを
タップして数え足せるようになります。キーが暗くなるのは、4回目に 👆 の手が
やり方を見せ終えてからです。

**足場も外します。**　キーパッドは当てずっぽうを塞ぎましたが、*数える*道は
開いたままでした。「2と いくつで 10？」の下に青2つと空マス8つが並んでいれば、
空マスを1つずつ数えれば 8 に着きます。思い出していなくても正解できる、
ということです。いま、いくつと いくつ L3 と 10の おともだち L2 では
テンフレームを**最初は出しません**。出るのは (1) 2回まちがえたときのヒント、
(2) 答えたあと——確認として。式（「2 と ? で 10」）は問題なので残ります。
たしざん・ひきざん L3 は元からこの形でした。

**速さを測ります。**　「1回目で正解」だけを見ていると、空マスを9秒数えて
8 と押した子と、1.2秒で押した子が同じ記録になります。くり上がりの計算で効くのは
後者だけです。いまは問題が出てから最初に答えるまでの時間を記録し、
正解だったときだけ、事実ごとに（けいさんの やま の4遊びに限って）残します。

- **3.0秒まで**＝思い出している／**9.0秒を超える**＝数えて出している
- 正解でも遅い事実は `factDue` が「まだできていない」として扱い、
  「にがて あつめ」が拾います。**「できるけれど、数えている」は保護者ページに
  専用の欄で出ます**——正答率だけでは絶対に見えなかったものです
- ★★★（全問一発正解）に加えて、そのうち75%以上が3.0秒以内なら
  **「かぞえないで こたえられたね！」**が出て、レベル選択に ⚡️ が残ります
- 急かしません。制限時間もカウントダウンも入れず、終わったあとに褒めるだけに
  使います。物語や指なぞりの遊びでは、そもそも時間を測っていません

**まちがえ方に、型があります**　`noteFact` が受け取っていたのは
「一発で正解したか」と「かかった時間」だけで、`onWrong(target)` は
子どもが押したボタンそのものを引数で持ちながら、値を捨てていました。だから
記録が言えるのは「10は4といくつ、が62%」まで。**4 と答えた**（見えている方を
そのまま言った）のか、**5 と答えた**（1つずれた）のか、**7 と答えた**（見当が
ついていない）のかは、どれも同じ 62% でした。三人とも別の子で、
台所でかける言葉も別です。

1回目のまちがいの値を分類して数えます（`src/js/06-miss.js`）。

| 型 | 子どもに出ることば | 保護者ページの文 |
|---|---|---|
| `up` / `down` | もういちど、ゆびで さしながら かぞえて みよう | 1つ多く／少なく数えています |
| `part` | それは みえて いる ほうの かずだね | 答えではなく、問題に出ている数をそのまま答えています |
| `whole` | それは ぜんぶの かずだね | 全体の数を答えています |
| `opp` | ＋か −か、もういちど みてね | たし算とひき算を取り違えています |
| `rev` | かぞえる むきを たしかめてね | 反対の端から数えています |
| `hand` | みじかい はりを みてね | 長針がさす数字を「何時」として読んでいます |
| `looks` | おおきさ じゃなくて、かずを かぞえて みよう | 数ではなく、見た目の大きさで選んでいます |

型は2通りの付き方をします。**エンジンが読む**（`buildChoices` / `buildPad` は
答えと押された値の両方を知っているので、遊び側の変更は不要です）か、
**遊びが名乗る**（`api.wrong(el, 'looks')`）か。後者は項目キーに書けないことのためです。

いちばん惜しかったのが **どっちが おおい L2「ちかい かず」**でした。
`compareClose` は 60% の確率で*少ない方*をわざと2倍の大きさで描きます。
見た目に惑わされずに数で判断できるか——このレベルの存在理由そのものなのに、
その子が見た目で選んだかどうかを、アプリは記録していませんでした。

保護者ページには「まちがえ方の型」が出ます。**「10は4と6：62%」ではなく
「1つ多く数えています（のべ6回・かぞえよう／10の おともだち）」**です。
正答率だけを見ていて絶対に出てこないのはここで、家庭での声かけを変えられるのも
ここです。速さの軸（できるけれど数えている）と同じ理屈の、3本めの軸です。

**まちがえた後の手当ては、やり方に戻す段です**　以前は1段でした。2回目でヒントが出て、
そのあとは何も起きません。段階的な救済（不正解の選択肢を1つずつ暗くする）は
`buildChoices` が作ったボタンにしか掛からず、**60レベル中28レベル**——
キーパッドの10と、皿・行・時計の針・ドラッグといった自作の回答面の18——では
暗くするものが無いからです。いくつと いくつ L3 で5回続けて間違えると、
3・4・5回目のスクリーンショットは**1ピクセルも違わず**、吹き出しは
「ヒントを だすね」のまま止まっていました。

その後「暗くする」を全部に掛けましたが、調べると別の穴がありました。

- **ヒントの中身が声になっていませんでした。**読み上げるのは「ヒントを出すね」だけで、
  中身まで読むのは60レベル中2つ。🔊 も問題文しか読み直しませんでした
- **3択で別々の答えを2つ押すと、ヒントの瞬間に正解しか残りませんでした**（13レベル）。
  試した選択肢を灰色にしていたからで、ヒントを使わなくても押せました
- **12レベルは、ヒントで盤面が何も変わりませんでした**（かぞえよう、すうじ どれかな、
  いくつと いくつ L1・L2、たしざん／ひきざん L1・L2 など）
- **約10レベルは、ヒントが答えそのものでした。**お皿に「5こ」、並んだ動物に番号、
  正しい箱や穴を光らせる
- **「こたえを みる」は、答えを言って正解ボタンを押すだけ**で、なぜそうなるかは見せませんでした

うまくいっていたヒントは、答えを言わずに**比べ方をやって見せる**ものでした——
ながさの棒が端にそろう、かさの同じ大きさのマス、ぱっと みて のもう一度見せる。
それを全遊びの型にしました（`src/js/07-coach.js`）。

| まちがい | 起きること |
|---|---|
| 1回目 | 型が分かればその言葉で、分からなければ「もういちど やってみよう」 |
| 2回目 | **その遊びの道具**が盤面に出て、**声で言います**。数えられる（タップで番号）、あいたマスを埋めて数え足す、お皿の中身を同じ大きさで5こずつ並べる、棒に目盛り、とけいの短い針を光らせる…。**選択肢は減らしません** |
| 3回目 | 「まだ ちがうね。ヒントを つかって みよう」と、道具の言葉をもう一度 |
| **4回目** | **👆 の手が、やり方を最後まで見せます**（そのあいだ指の入力は止めます）。見せ終えてから、キーパッドを答え±1に、3択は2つに。**「こたえを みる」**が出る |
| **6回目** | 押されなければアプリが押します。まだ手が見せていなければ、先に見せてから答えます |

道具は答えを書きません。どっちが おおい は数を書く代わりに「見た目の大きさ」という
罠を外し（同じ大きさ・5こずつ・同じ端から）、なんばんめ は数え始めの1ぴきにだけ「1」を
付け、なかまわけ は正しい箱ではなく箱の絵を光らせます。答えまで見せるのは4回目の手だけです。

6回目（または「こたえを みる」）で終えた回は `taught` として記録され
（空欄が2つ以上ある問題でも、次の空欄に進んだところで消えません）、
**★にも「1回目で正解」にも数えません**。保護者ページが回数を報告し、
「にがて あつめ」が必ず拾います。**3回まじめに挑戦すれば次のレベルが開く**のと
同じ考え方を、1問の中にも入れた、ということです。5歳を、動かせない扉の前に
置かないためです。

正解の押し方はキーパッド・3択なら**その問題自身のボタンを押す**ので、
`revealed()` が答えを式の中に書き戻すところまで、ふつうに正解したときと
同じことが起きます。自作の回答面は `api.onShow(fn)` で「正しい操作を自分でやる」
一行を登録できます（登録が無くても、問題は必ず終わります）。

## 当てずっぽうでは、シールに色がつかない

クリアは「8問中4問を1回目で正解（★1）」です。3回挑戦すれば次のレベルは開き、
「いまの おすすめ」は休ませたレベルにまた戻るので、同じレベルに何度も挑むのは
ふつうの流れです。そこで、**でたらめに押すだけの子**を実際の出題器で走らせました
（各レベル60回、タップで答える入学前の36レベル）。

| レベルの例 | 答え方 | 1回で クリア | 3回以内 | 6回以内 |
|---|---|---|---|---|
| どっちが おおい L1・L2 | 2択 | 約65% | 約95% | ほぼ100% |
| ひきざん L2 | 3択 | 37% | 75% | 94% |
| たしざん L2／おなじ かたち | 3択 | 33% | 70% | 91% |
| いくつと いくつ L1 | 3択 | 30% | 66% | 88% |
| いくつと いくつ L3 など | キーパッド | 0% | 0% | 0% |

**36レベル中25レベルが、でたらめでも6回以内に半分以上の確率でクリアできました。**
（二項分布の理論値：2択64%・3択26%・4択11%・キーパッド0.4%とほぼ一致）。そのシールが
1ねんせいの扉の鍵で、「いまの おすすめ」の「終わった」でした。

いまは、★1〜★2 のクリアは **かりの シール**（輪郭だけ・灰色）になります。

| 色がつくとき | |
|---|---|
| **別の日の確かめ** | 次の日の最初のレベル（または「きょうの れんしゅう」）の頭に、そのレベルから3問。2問を1回目で正解すれば色がつく。確かめは1レベル1日1回、レベル遊びでは1レベル分・れんしゅうでは2レベル分まで。この3問はいま遊んでいるレベルの★には数えない |
| **別の日にもう一度クリア** | そのレベルを別の日に★1以上で終えれば、それが確かめ |
| **★★★** | 8問すべて1回目で正解は、当てずっぽうでは届かないので、その場で色がつく |

**確かめを当てずっぽうにしない。**2択の問題は確かめのときだけ3択にします
（どっちが おおい はお皿を3枚、すうじ くらべは数字を3つ、かさくらべはコップを3つ、
なかまの ならびは3列）。答えがひとつに決まらない問題（2とおりに わける・自分で
きまりを作る・3つで10・自分で なかまを決める）は、どれを押しても正解になるので確かめには出しません。

3択なら、でたらめな子がクリア（26%）と1回目の確かめ（3問中2問＝26%）の両方を通るのは約7%です。
7割わかっている子は、1回の確かめで約78%が通ります。**確かめで届かなかったレベルは、
シールはかりのまま、「いまの おすすめ」がもう一度そのレベルを出します。**クリアした日のうちは
おすすめは次へ進むので、クリア直後に同じレベルへ戻されることはありません。

扉が開くまでの日数への影響は、**まだ測っていません。**1日1レベルのペースなら、前の日の
クリアは次の日のいちばん最初に確かめられるので、大きくは延びない見込みです（確かめで
届かないレベルが多い子ほど延びます）。

保護者ページの「これまでの積み重ね」に「かりのクリア（別の日の確かめ待ち）」が出ます。
バックアップを「合体」したとき、どちらかの端末で色がついていれば色つきです。

## 新しい考え方は、まちがえる前に見せる

ヒントを段にしても、**新しい考え方との最初の出会いは、いつも本番の問題**でした。
「はん」を初めて見るのは とけい L2 の1問目で、「はん」の説明が届くのは2回まちがえた後です。
レベルの説明や見本の仕組みは、アプリのどこにもありませんでした。

いまは、**そのレベルをまだ遊んだことがない**（プレイ0回で、れんしゅうでも4問未満）ときだけ、
8問の前に2問が入ります。

| | 何が起きるか | 記録 |
|---|---|---|
| **みてて** | 「はじめてだね。見ててね」＋問題文。👆 の手がやり方を最後まで見せて、答えまで押す。そのあいだ指の入力は止める | ★にも項目の記録にも数えない |
| **いっしょに** | 問題が出た瞬間に、その遊びの道具（数える・マスを埋める・端をそろえる…）が出て声で言う。答えるのは子ども | 同上。終えるとそのレベルは「見せた」になり、次からは入らない |

進み具合の点（上の ● の列）は、この2問だけ輪で出ます。手の動きは4回目のまちがいで
出るものと同じ部品（`coach.walk`）なので、問題ごとに2回書くことはありません。
数えてから聞く・話を見てから答える、のように段がある問題は、段ごとに見せます。

**きょうの れんしゅう**が、まだ開いたことのないレベルの問題を出したときは、その1問を
「いっしょに」で出します（1回に2問まで。れんしゅうのままにしておくため）。

**👀 みせて**　問題の吹き出しの横にあります。1回目で道具、2回目で手の見本。
助けを取りにいけるのが、まちがえた後だけではないようにです。押した問題は自力の正解には
数えず（★には入らず、「とっくん」が拾います）、まちがえ方の型にも記録しません。

**★と解放**　★は「一発で正解した問題の割合」で付きます。全問=3、75%以上=2、
50%以上=1、それ未満=0。★0 では次のレベルは開きません。ただし
**3 回まじめに挑戦すれば開きます**。5 歳児を動かせない鍵の前で止めないためです。
シールは ★1 以上のときだけ出ます。

進め方の目安（保護者ページにも掲載）
1. **1〜2か月め** かずの しま を中心に。まず 10 までを確実に
2. **3〜4か月め** いくつと いくつ → 10の おともだち。ここが山場
3. **5〜6か月め** たしざん・ひきざん と、とけい・くらべる系で入学後の単元に先に触れる

## 半年を、アプリが数える

`createdAt` は保存されるだけで誰も読まず、保護者ページのロードマップは
「1〜2か月め…」という**固定の文章**でした。3か月めの過ごし方を説明しながら、
この子が3か月めにいるかどうかを知らない、という状態です。

入学の日は**はじめて使った日から推定**します（4月以降に始めたなら翌年の4月1日、
それより前ならその年の4月1日）。年中さんなど推定がずれる場合は、保護者ページの
「1年 早める／遅らせる」で動かせます。

保護者ページの「入学まで」が出すのは3つです。

- **あと ◯日**（入学予定日つき）と **◯/48 レベル**
- **このペースでの到達見込み**——「使い始めてから 40日で 12レベル（週 2.1レベル）。
  のこり 36レベルを同じペースで進めると 1月8日ごろ」。単純な平均だと明記してあります
- 間に合わないときの**追いつき方**（おすすめを毎日1回・8問／繰り返すより にがて あつめ）。
  間に合わなくても内容は消えない、と書いてあります

ロードマップの表は、いまいる時期の行に「← いまここ」が付きます。

## のこりが、名前で見えていること

シールブックの空きスロットは「･」でした。「あと 4レベル」と分かっても、
その4つがどれかは分かりません——48枚目前で止まっている子には、
それがいちばん要る情報です。

いまはシールブックの上に **「のこりの レベル」** が並びます。遊びの名前と
レベル名のチップで、開いているものはタップでそのまま始まり、まだ開いていないものは
鍵マークでレベル選択へ飛びます。「いまの おすすめ」が歩くのと同じ順で、並べるのは
**扉がまだ待っているレベル**（色のついたシールが無いレベル）です。かりのシールのレベルも
「・たしかめ」と付けて並びます。

ホームの**シール棚**も一行変わりました。以前ここは「タップで シールブック」でしたが、
`1024×768` の横向きだと世界一覧はスクロールする領域（509px の窓に 1079px の地図）で、
README が「初日から見えている」と書いた 1ねんせいの鍵付きカードは実際には y≈900、
2/3までスクロールしないと出てきません。地図をいじる代わりに、
**必ず画面にある棚**が「1ねんせいの きょうしつまで あと ◯レベル」を言います
（残り6レベルを切ると色が付きます）。

## 記録が消える前に、一度だけ聞く

記録は localStorage 1つで、iPadOS はそれを捨てることがある——と、この README 自身が
書いています。それなのに書き出しは保護者ページ（掛け算ゲートの奥）にあるだけで、
アプリの側からは一度も言いませんでした。

- 10日以上使っていて、**一度も書き出していない／30日以上書き出していない**ときだけ
- ホームの **「おうちのかたへ」ボタンに小さな印**が付きます。子どもの画面はそれ以外
  何も変わらず、読み上げもしません
- 保護者ページの「記録の保存とバックアップ」に理由が出ます。書き出す／コピーすると
  印は消え、**いつ書き出したかもバックアップに入ります**

## なまえ

`Store` の `name` は初版から保存され、バックアップでも検証され、**どこからも
読まれていませんでした**。保護者ページの設定で入れると、タイトルが
「◯◯の ぼうけん、はじまるよ」、シールブックが「◯◯の シールブック」になり、
★★以上でクリアしたときに名前で褒めます。

**プロフィール機能ではありません。** 記録はこの端末に1人ぶんのままで、きょうだいで
1台を使えば混ざります。分けるなら書き出したファイルを1人ずつ保管し、遊ぶ前に
「おきかえる」で読み込んでください——保護者ページにもそう書いてあります。

## iPad に入れる

**方法 A：ホーム画面に追加（おすすめ）**
1. `dist/kazu-no-bouken.html` を iCloud Drive などに置くか、任意の場所に公開する
2. Safari で開く → 共有ボタン → 「ホーム画面に追加」
3. アイコンから起動するとブラウザの UI が消え、アプリのように全画面で動く

**遊びはじめる前に追加してください。**　iPadOS では、ホーム画面に追加したアプリの
記録が Safari のタブとは別に保存されることがあり、タブで数日遊んでから追加すると
アイコン側は空から始まります。すでにタブで遊んでいたら、追加する前に保護者ページで
書き出し、追加したアイコンから開いて読み込んでください。Safari のタブで保護者ページを
開くと、同じことが書いてあります。

**方法 B：ファイルをそのまま開く**
`dist/kazu-no-bouken.html` を AirDrop などで iPad に送り、ファイルアプリから Safari で開く。
ただし `file://` で開くと iPadOS 側がデータ保存を許可しないことがあり、**その場合は
学習の記録が毎回消えます**（保護者ページに警告が出ます）。半年続けるなら方法 A を
使ってください。ホーム画面に追加していない Safari のタブも、7 日間使わないと
iPadOS が保存データを破棄します。

**オフラインで動きます。** 公開したページ（GitHub Pages など）から一度開けば、
Service Worker がアプリ本体・アイコン・フォントをキャッシュするので、
以後は機内モードでも起動します。新しくデプロイした版は、次に起動したときに
自動で入れ替わります（表示は先にキャッシュから出るので、待たされません）。
AirDrop したファイルを直接開く場合は、そもそも通信しないので最初から
オフラインで動きます。フォントだけは iPad 内蔵のヒラギノ丸ゴにフォールバックし、
見た目が少し変わります。

Service Worker を登録しておくと、iPadOS がこのサイトを「インストール済み」として
扱うため、記録（localStorage）を勝手に捨てられにくくなる副作用もあります。

## 記録が消えないようにする

学習の記録は **localStorage** に入ります。ここには 2 つの落とし穴があります。

1. **記録は URL（オリジン）ごとに完全に別物です。** GitHub Pages の URL、Artifact の URL、
   AirDrop で渡したファイル（`file://`）は、同じアプリでも互いの記録を見られません。
   **使う入り口をひとつに決めてください。**
2. **ホーム画面に追加していない Safari のタブは、7 日使わないと iPadOS が保存データを
   破棄します。** ホーム画面のアイコンから起動していれば対象外です。
3. **Safari のタブとホーム画面のアプリは、記録が別になることがあります。** タブで
   遊んでから「ホーム画面に追加」すると、アイコン側は空から始まります。
   追加する前に書き出し、追加後に読み込んでください。

**「書き出した」と記録するのは、本当に保管できたときだけです。** 共有シートが使える
端末（iPad など）では共有シートで渡し、共有が終わった時点で記録します（取り消したら
記録しません）。使えない環境ではファイルを保存させ、大人が「保存できた」を押した
時点で記録します。「コピー」も、貼り付けて保管してから「保存できた」を押します。
以前はダウンロードのリンクを押した瞬間に記録していたので、ホーム画面から起動した
iPad のように保存が実際には効かない環境でも、ホームの印が消えていました。

そのうえで、保護者ページに **書き出し／読み込み** を用意しています。

- **記録を書き出す（ファイル）** … `kazu-no-bouken-YYYYMMDD.json`（数 KB）を保存
- **コピー** … 同じ内容をクリップボードへ。メモアプリに貼って保管できる
- **記録を読み込む** … ファイルを選ぶか、枠に貼り付けて復元
- **読み込み方** … 「合体する」（既定）はいまの記録と読み込んだ記録の良いほうを残す。
  同じファイルを二度読み込んでも数字は増えません。「おきかえる」は丸ごと差し替え

端末を変えるとき、URL を移すとき、Safari のデータを消す前に書き出しておけば復元できます。

**動作要件**：iPadOS 16.2 以降（`color-mix()` と `:focus-visible` を使っています）。
それ以前の iPad では図形の輪郭など一部の色が出ません。

**音声について**：問題文は日本語で読み上げられます。文字だけでも遊べます。

声が機械的・単調に聞こえるときの直しかたは 2 つあります。

1. **保護者ページ → 設定 → 読み上げの声** で、端末に入っている日本語音声を
   選び直す。「試しに聴く」で聴き比べられます。Kyoko は昔からある合成音で、
   Flo・Sandy などは Siri と同じ新しいエンジンの声です。選んだ声は記憶されます。
2. iPad の **設定 → アクセシビリティ → 読み上げコンテンツ → 声 → 日本語** で、
   「高品質」または「プレミアム」の音声をダウンロードする（無料・オフラインで
   使えます）。名前は同じままで、声だけが自然になります。ここでの差がいちばん
   大きいので、単調さが気になるならまずこれを試してください。

読み上げ用の文だけは漢字と句読点で書きます（`api.setPrompt` の第 2 引数）。
日本語の音声合成は文を解析して抑揚と句切りを決めるため、全部ひらがな＋分かち書き
だと平坦な棒読みになるからです。画面に出る文は子どもが読むのでひらがなのままです。

## 公開（GitHub Pages）

## テスト

```bash
python3 -m http.server 8731     # プロジェクト直下で
```
ブラウザで `http://127.0.0.1:8731/test/index.html` を開くと回帰テストが走ります。
アプリを iframe に読み込み、実際に答えをタップして「そのあと何が起きたか」を検証します。

問題を **作れる** ことだけを確認しても、対話のバグは1つも見つかりません。
実際に初版では、正解を押した後の挙動を誰も検証していなかったために、
「穴が2つある問題が1つ目で終わってしまう」「前の問題のタイマーが次の問題を
勝手に正解にする」といったバグが素通りしていました。テストはそこを狙って書いてあります。

| 検証 | 何を守っているか |
|---|---|
| no question completes while blanks remain | 複数回答の問題が途中で終わらない |
| one answer never advances more than one question | 1回の正解で1問だけ進む |
| every level is playable through to the result screen | 全60レベルが最後まで遊べる |
| leaving a question cannot advance the next level | 中断しても前の問題のタイマーが残らない |
| a story animation cannot write into the next question | アニメ中に抜けても次の画面を壊さない |
| leaves no handlers behind | 共有ノードにリスナが溜まらない |
| a hint is never stacked up | ヒントが重複しない |
| two wrong answers always change something on screen | 読み上げオフでも必ず画面が反応する |
| tracing motor slips do not lower math stars | 始点を外した運筆ミスを、算数の誤答として減点しない |
| tapping the correct answer twice cannot strand the question | 二度タップで空欄を飛ばさない・例外を出さない |
| one session works through the fact set | 1回のレベルが同じ事実を出し続けない |
| a session under half right earns no star | 半分に満たない回で次が開かない |
| three honest attempts open the next level | 3回やれば必ず先へ進める |
| a clear pass opens the next level | 通れば開く |
| the daily set aims at the weak topics | 弱点を厚く出しつつ他も捨てない |
| にがて あつめ meets every weak fact several times | 苦手な事実が 1 回のすわりで 3 回以上出る |
| a fact with nowhere to be asked again is never offered | 出題場所が分からない古い記録を練習に出さない |
| an aimed set with nothing to aim at falls back | 対象がないときに空の回が始まらない |

## 遊びを増やす

`src/js/1x-g-*.js` に `Games.add({...})` を足すだけで、ホーム画面・レベル選択・
「きょうの れんしゅう」・保護者ページのすべてに自動で載ります。

```js
Games.add({
  id: 'myGame', name: 'あたらしい あそび', ico: '🎲',
  world: 'shima',                 // shima | umi | yama | mori | kyoshitsu
  color: 'var(--c-blue)',
  // stage: 'g1',                 // 付けると「1ねんせいの きょうしつ」側になり、
                                  // 入学前を全部クリアするまで出題には出ません
  aim: '保護者ページに出る「この遊びで つく ちから」',
  levels: [
    { t: 'レベル名', d: 'ひとこと説明', n: 8, make(api){
        api.setPrompt('といかけ', '読み上げる文。');   // 音声側は漢字＋句読点で
        api.field.append(/* 問題の見た目 */);
        api.item('myGame:3', '3 の れんしゅう');   // この問題が聞いていること
        api.buildChoices([1,2,3], 2);   // 正解は 2
        api.coach({                       // つまずいたときの手当て（下の説明）
          text: 'ひとつずつ かぞえよう', say: '一つずつ、数えよう。',
          tool(){ /* 2回目：盤面を「解き直せる形」に */ },
          walk(){ return [/* 4回目：手が見せる手順 */]; }
        });
      } }
  ]
});
```

数で答えるレベルは `api.buildChoices` の代わりに `api.buildPad(answer)` を
使ってください。位置の変わらない 0〜10 のキーパッドが出ます。

**答えは問題の中に書き戻してください。**　`?` を残す問題を作ったら、
`revealed()` でその `?` を埋めます。次の問題までの間も自動で伸びます。

```js
const box = el('span.box', { text: '?' });
api.field.append(el('div.eq', null, String(a), el('span.op', { text: '＋' }), String(b),
                    el('span.op', { text: '＝' }), box));
api.buildPad(ans, revealed(() => fillBlank(box, ans)));
```

**`api.want`**　「にがて あつめ」の回では、その問題で聞いてほしい事実を
エンジンが名指しします（項目キーの、遊び ID を除いた部分。ふだんは `null`）。
読めば一発でその事実を出せます。

```js
const w = api.want && /^ten:(\d+)$/.exec(api.want);
const a = w ? Number(w[1]) : ri(1, 9);
```

読まなくても壊れません。エンジンが最大 24 回まで引き直し、当たらなければ同じ
レベルの別の問題で妥協します（狙った事実ではないが、狙った力ではある）。
けいさんの やま の生成器は全部 `api.want` を読みます。

`api.correct()` を呼べば正解、`api.wrong(el)` で不正解。自作の操作で解かせる遊びは
この 2 つを自分で呼べば、進行・星・シールはエンジン側が面倒を見ます。

**`api.wrong(el, given)` の第2引数**　その子が実際に選んだものです。数や文字列を
渡すとエンジンが答えと突き合わせて型を判定し、項目キーに書けない型は自分で
名乗れます（`'looks'` `'rev'` `'hand'` など、`MISS_KINDS` のキー）。
省略しても壊れません——診断が付かないだけです。
`buildChoices` / `buildPad` を使う問題は、何もしなくても付きます。
自作の回答面で数を渡すなら、**`api.answer(v)` で正解も伝えてください**。突き合わせる
相手が無いと型は付きません（すうじ どれかな の皿はこれで「1つ多く」が付くようになりました）。

キーパッドの±1は、すぐ（1.5秒以内）正解に直したら指のずれとみなし、「1つ多く／少なく
数えている」には数えません（1回目の正解にはなりません）。答えるまでの時間は、問題文の
読み上げが**終わってから**数えます。

```js
api.wrong(plate, looksBigger ? 'looks' : null);
```

**`api.coach({ text, say, tool, walk, after })`**　つまずいたときに何を渡すかです。
すべて省略できますが、書いてください。

- `tool()` … 2回目のまちがいで呼ばれ、盤面を**子どもが解き直せる形**にします。
  答えを書いたり、正しい選択肢を光らせたりはしません。`Coach.countable(api, nodes)`
  （タップで番号を付けて数える）、`Coach.fillable(api, cells, { from })`（あいたマスを
  埋めて数え足す）、`Coach.ticks(wrap)`（棒に目盛り）、`Coach.pulse(node)` が使えます
- `text` / `say` … 吹き出しの文（ひらがな）と読み上げの文（漢字）。関数でも可。
  `tool` を書くと、エンジンはヒントで選択肢を暗くしません
- `walk()` … 4回目に 👆 の手がたどる手順 `[{ at: node, say, act(){}, ms }]`。
  やり方を見せるだけで、答えのボタンは押しません（押すのは6回目のエンジン）
- `after` … 何回目で `tool` を出すか（既定 2）

```js
const cnt = Coach.once(() => Coach.countable(api, $$('.item', row)));
api.coach({
  text: 'ひとつずつ タップして かぞえよう', say: '一つずつタップして、数えよう。',
  tool(){ cnt(); },
  walk(){ return cnt().steps(); }
});
```

以前の `api.onHint(fn, after)` も動きます（`tool` として扱われます）。

**はじめて開いたときの見本も、この `walk` で出ます。**見本は「`walk` を歩く → 答えを押す」を
段ごとに繰り返すので、次の2つを守ってください。

- 答える前に子どもの操作が要る段（数える、「みる」を押す）にも、その段の `walk` を持つ
  `api.coach({ walk })` を置く（まちがえようがない段なので `tool` は要りません）
- 自作の回答面には `api.onShow(fn)` を書く。見本の最後はそれで答えます。
  無いと見本が止まり、回帰テスト「the hand can show every game all the way to an answer」が落ちます

手で見せられない遊び（なぞり書き）は `Games.add({ …, intro: false })` にします。

**`api.onShow(fn)`**　6回まちがえたときに、正しい操作を代わりにやる一行です。
3択・キーパッドの問題は要りません（エンジンが正解のボタンを押します）。
自作の回答面だけ、自分の正しい要素をタップしてください。

```js
api.onShow(() => { const p = $$('.plate', wrap).find(x => +x.dataset.count === answer); if (p) p.click(); });
```

**`api.item(key, label)` を呼んでください。** その問題が何を聞いているかの申告です。

```js
api.item('ten:' + a, a + ' と ' + (10 - a) + ' で 10');
```

これがあると、(1) 同じ事実が 1 レベル内で繰り返されなくなり、
(2) 間違えた事実が「きょうの れんしゅう」に戻ってきて、
(3) 保護者ページの「つまずいている中身」に `label` がそのまま出ます。
申告しない遊びは従来どおり完全ランダムに出ます（壊れはしません）。

`Games.add` の `focus`（既定 1）はカリキュラム上の優先度で、
「きょうの れんしゅう」の重みに掛かります。いくつと いくつ／10の おともだちが 1.7 です。

**`stage`（既定 `'pre'`）** は、その遊びがアプリのどちらの半分に属するかです。
`'g1'` を付けた遊びは「1ねんせいの きょうしつ」に入り、入学前のシールが
全部そろうまで、ホームにも「きょうの れんしゅう」にも「いまの おすすめ」にも
出てきません（`stageOpen` / `levelOpen`）。入学前側に遊びを足すと解放条件の
シール枚数も自動で増えます。`STICKER_POOL` の絵文字が足りているかだけ、
テストが見張っています。

問題の見た目は、書いたあとにエンジンが `--u` を伸縮させて playfield いっぱいに
合わせます（`UI.fitPlayfield`。上限は 2.9 倍——2.4 だと縦向きの iPad で
かぞえよう L1 が盤面の 79% を空けたまま、指で触る対象が上限に張り付いていました）。サイズは `--u` の倍数で書いてください。
`px` 直書きは拡大されません。

**遅延処理は必ず `api.later(fn, ms)` を使ってください**（`setTimeout` は使わない）。
問題を離れると自動でキャンセルされるので、アニメーションの途中で「もどる」を
押されても、前の問題が次の問題を書き換えることがありません。

複数の答えを順に聞く問題は `buildChoices` の `onPick` で `false` を返します。
`false` のあいだ問題は開いたままになり、最後の正解でだけ次へ進みます。

```js
api.buildChoices(values, answer, {
  onPick(){ /* 1つ埋める */ return more ? false : true; }
});
```
